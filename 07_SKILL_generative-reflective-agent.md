# Generative Reflective Agent Skill

## Mission
Add a small number of "reflective" agents whose actions/thoughts are occasionally
generated by a real LLM call, conditioned on their belief state (Layer 2) and an
accumulated memory stream — the closest realistic analog to a "waking up" character,
inspired by the Generative Agents (Park et al., 2023) memory/reflection/planning loop.
This is NOT a claim of simulating consciousness — it's a practical way to get richer,
more legible agent narratives layered on top of the statistical model underneath.

## When to use
- Layers 0-3 are already working and stable.
- You want a small number of agents to produce human-readable "internal monologue" or
  belief-justification text instead of just numeric belief values.
- Prototyping the "SPM in a society of LLM agents" research extension mentioned in
  `01_MASTER_INSIGHTS.md` section 5.

## Instructions

1. **Scope tightly — this layer is expensive.** Only 1-5 agents should ever be
   "reflective" at once, selected manually or by simple rule (e.g. the agent with the
   most extreme belief, or the first sleeper agent to trigger). Do not call the LLM for
   every agent every tick — this will not scale and isn't the point of the layer.

2. **Namespace** — `agent.generative = { memoryStream: [], lastReflection: "",
   callInFlight: false }`.

3. **Memory stream** — append short structured entries each time something notable
   happens to the agent (belief shifted significantly, received a misinformation
   signal, energy critically low). Keep entries short (one line each); don't dump raw
   per-tick state into memory or the prompt will blow up.

4. **Trigger the LLM call sparingly** — on a timer (e.g. every 30-60 seconds of sim
   time) or on a significant event (belief crossed a threshold), not every tick. Guard
   with `callInFlight` so overlapping calls don't fire.

5. **Prompt structure** — send the agent's current belief value, a short summary of
   recent memory entries, and ask for a brief first-person reflection or next
   intention. Keep the system/context prompt short and consistent across agents; vary
   only the per-agent memory and belief data. This keeps API cost predictable — mirrors
   the token-constrained Commander agent design already used in the bullet-heaven game
   project.

6. **Display** — show the latest reflection as a speech-bubble/tooltip when the agent
   is selected, alongside the belief/brain inspector panels from earlier layers, rather
   than as a separate disconnected UI element.

7. **Failure handling** — if the API call fails or is slow, the agent should keep
   behaving normally via its Layer 1/2 rules; never block the simulation loop waiting
   on a network call.

## Validation checklist
- [ ] LLM calls are capped to a small, bounded number of agents
- [ ] Calls are rate-limited/event-triggered, not per-tick
- [ ] Simulation continues running normally if a call fails or is slow
- [ ] Reflections are visibly grounded in the agent's actual belief/memory state, not
      generic text
- [ ] Token usage per call stays small and predictable (short prompts, short memory
      entries)
